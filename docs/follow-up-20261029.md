## 两项覆盖问题及修正

### zsmalloc 类字段与重复页

按 [Linux v4.4.302 zsmalloc 源码](https://github.com/gregkh/linux/blob/v4.4.302/mm/zsmalloc.c)，`FULLNESS_BITS` 为 4，`ZS_FULL` 的枚举值为 4。早先按 2 位解释、只接受较小 mapping 的做法漏掉了页链；旧结果中的类索引和对象大小假设不能用于对象偏移。旧页链经过互证且严格解压成功的字节仍可保留。

修正后识别出 4,163 条互证链，其中 3,629 条不按物理地址连续排列，并新增提取出 4,449 个不同的完整 LZO 解压页。

**这 4,449 是新提取的 LZO 表示数，不是 4,449 份此前从未检查的内存内容。** 对原始 RAM 和逻辑交换副本做整页去重后，4,381 份已有相同字节，68 份未找到页对齐匹配。没有整页匹配也不等于从未部分覆盖。此前把全部解压页称为“此前未检查页”的说法已更正。

另检查了解码器在截断或损坏输入上产生的前缀。这些前缀作为待验证假设保存，不计作完整内存页、用户文件或恢复成果。

### 交换 PTE 编码

早期检查使用了原始 4.4 的交换页编码；本机实测匹配 [Linux v4.4.302 的 x86-64 编码](https://github.com/gregkh/linux/blob/v4.4.302/arch/x86/include/asm/pgtable_64.h)。按 64 位值处理时，本次使用：

```text
swap_type   = pte >> 59
swap_offset = ((~pte) >> 9) & ((1 << 50) - 1)
```

旧的交换映射阴性结果不能用于排除换出页。修正后通过真实交换槽和完整页表链验证了解码，再重做参考构建固定地址检查，仍没有取得主材料候选。这一布局验证只针对本机，不直接套用其他内核。

此外，重组了 **35,705 份至少一侧换出的候选虚拟页边界**。其中保留原逻辑交换副本，以及可严格解码且内容发生变化的 RAM 时点 zram 版本。候选页表及跨时点拼接不等于已证明的历史进程映射，所有材料仍须接受密文验证。
