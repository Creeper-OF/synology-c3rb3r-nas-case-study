# ext4 系统分区补查：来源属性、已删除 inode 与清理日志

本轮只检查先前保存的系统分区镜像、只读工作副本和已有 RAM/交换副本，没有访问 NAS 原盘、挂载镜像或回放 journal。结论核对至 **2026-10-29 23:05（UTC+8）**。公开数据见 [ext4-findings.json](../evidence/ext4-findings.json)，证据定位为 E21–E23。

**本机恢复出了与独立公开案例逐字相同的投递 URL，以及两条可核对到镜像字节的清理日志。尚未恢复原始 `libgld` inode，也未获得解密密钥。** 相同端点和兼容的清理行为支持基础设施关联；同一二进制、精确投放批次和操作者身份仍未证明。

## 镜像及检查范围

对象是 ext4 根系统分区镜像，大小 **2,549,940,224 字节**，不是全盘镜像。私有采集记录显示：18:37:12 开始、18:40:54 结束，18:41:44 完成本地摘要核验。它来自运行中的系统顺序读取，各区域状态可能属于不同时间，不是原子快照。

原镜像与权限为 `0444` 的分析副本在检查后均保持以下 SHA-256：

```text
de9d9cfca467479424180f22cd4590a481ab6b4e67031201068c610361fa36dd
```

使用 `debugfs` 时没有传入 `-w`。原件以只读方式读取，分析输出另存。原件摘要与早于公开回复的本地采集时间有助于所有者核对保全链；仓库没有发布镜像或可信第三方时间戳，第三方不能仅凭这些摘要独立重现原始发现。

## 找到 libgld 的删除目录项，inode 已复用

本镜像 `/bin` 是指向 `usr/bin` 的符号链接。在 `/usr/bin` 的目录块 **10453** 残留区找到 `libgld → inode 43222`，该项不在活动目录项链中，另由 `debugfs ls -l -d` 核对。

| 定位 | 值 |
| --- | --- |
| 目录项起始镜像偏移 | 42,819,388 |
| 名称起始镜像偏移 | 42,819,396 |
| 条目头及名称十六进制 | `d6a80000c40006016c6962676c64` |
| inode 表块及槽位 | 块 3038、槽位 5 |

inode 43222 已被后续文件多次复用。现存槽位是 uid 1、大小 3 字节的已删除普通文件，所记 18:22:58 删除时间属于后续复用状态，**不能赋给原始恶意程序**。

通过保存 RAM 中的 `struct page` 映射与相邻 15 个 inode 槽位比对，定位到另一份旧 inode 表块；目标位置仍是后续 uid 1 日志文件。随后扩大到 journal 与更早的独立 journal 副本：

| 范围 | 不同的完整 inode 元数据版本 |
| --- | ---: |
| 本轮系统镜像与既有 RAM 等副本 | 226 |
| 更早保存的独立 journal 副本 | 243 |
| 两组重叠 | 222 |
| 两组去重后并集 | **247** |
| 原始 root 可执行 inode | **0** |

按完整 256 字节 inode 的 SHA-256 去重，更早副本贡献 21 个额外版本。247 是元数据表示数，不是文件数，也不是已证明提交顺序的事务数；没有任何版本把属性块 164366 绑定到这个 inode。

更早 journal 为 67,108,864 字节，SHA-256 为 `7e079ebf869d1fe99a1bb878c1c26738a70ec53e4d3ce6dd133aff0b7e93d801`。已解析的提交时间范围为 **15:19:25–18:20:50**，未保留凌晨攻击时段的提交时间。早期不完整根分区副本中的目标 inode 也已复用。因而本轮没有恢复可信的原始 `libgld` atime、mtime 或删除时间，更不能照搬另一受害者的时间或 OOM 结论。

## 跨案例关联能走到哪一步

可确认本机残留来源属性与公开案例记录**同一个精确下载端点**，`synot` 加三字母加 PID 的命名族及 `/bin/l0ck.enc` 清理行为也相容。推断两者关联到相同投递基础设施有较强依据。

尚无本机完整加密器，无法比较二进制摘要；原始 inode 和完整下载执行命令也未恢复。因此**不宣布同一精确投放批次、同一二进制或自然人归因**。另一个公开地址 `hxxp://104[.]253[.]175[.]125/xdy5[.]sh` 与本机恢复值不同；本镜像明文检索未命中该 IP、`init-rsysd.lo` 或 `0init-ld.lo`，此结果只限于现有镜像的明文字节。

本轮推进了投递与清理链条的证据，解密结论仍为未找到有效密钥。新的密钥补查见[晚间验证记录](late-key-validation-20261029.md)。
