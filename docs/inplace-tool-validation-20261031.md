# 10 月 31 日：原位解密工具副本测试

**固定版本的 Go 解密程序在有正确材料的四种合成布局下恢复出原文；同时复现了五项会影响取钥或原文件安全的行为。本案测试没有找到有效密钥，也没有新增真实文件解密。**

核对对象为 [penv13/c3rb3r-inplace-rescue](https://github.com/penv13/c3rb3r-inplace-rescue/tree/2a1408b8a73504f348d1126783a975d8d59abf6a)，提交 `2a1408b8a73504f348d1126783a975d8d59abf6a`。Go 版扫描器及恢复器从源码构建，在独立合成副本上运行；没有运行仓库预编译程序。C 版因测试机缺少 OpenSSL 开发头文件没有编译执行，以下运行结果不能代替 C 版测试。

## 测试范围与成功结果

公开前，重新从固定提交构建 Go 程序并在新建的合成目录复测；四种正确材料的布局及下列五项行为得到相同结果。共完成 **11 项合成场景检查**：两项扫描器正负对照、两项扫描边界、四项正确密钥恢复、以及错误 IV、目标文件碰撞和勒索信清理各一项。对缺陷场景，“检测到预期问题”不等于工具功能通过。

文件密文和分段布局由先前固定的独立参考实现生成，不使用待测恢复器自己生成密文。正确会话材料下，下列副本输出均与对应合成原文逐字节一致：

| 模式 | 合成文件原长 | 结果 |
| --- | ---: | --- |
| `0x24` 全文件 | 5,242,957 字节，跨 5 MiB 处理边界 | 一致 |
| `0x26` 文件头 | 2,097,229 字节 | 一致 |
| `0x25` / 10 | 13,631,565 字节 | 一致 |
| `0x25` / 20 | 17,825,833 字节 | 一致 |

扫描器在内部位置发现合成材料，阴性对照未命中。这些测试不证明所有文件格式、输入状态、并发设置或真实设备均可恢复。

## 五项复现的边界和风险

以下结果对应固定提交的 Go 程序，可能不适用于以后版本：

1. **最后窗口漏检：**单 worker、步长 1 的合成转储中，正确的 48 字节材料仅放在最后一个合法起点时未命中。范围划分见 [`scan_master.go`](https://github.com/penv13/c3rb3r-inplace-rescue/blob/2a1408b8a73504f348d1126783a975d8d59abf6a/src/scan_master.go#L62-L86)。
2. **零前缀跳过：**测试材料的 IV 前 4 字节为零时被过滤，虽然该材料的其他部分有效。源码也检查密钥前 4 字节；本项实际复现的是 IV 情况。[过滤条件](https://github.com/penv13/c3rb3r-inplace-rescue/blob/2a1408b8a73504f348d1126783a975d8d59abf6a/src/scan_master.go#L90-L97)
3. **错误 IV 报成功：**保留正确 AES 密钥，只改变 IV 的一位，程序仍报告成功并完成原位输出，但结果与合成原文不同。重复 nonce 在 CBC 第三块，不能验证只影响第一块的 IV；通过该检查不能代替真实文件验证。[解包与检查](https://github.com/penv13/c3rb3r-inplace-rescue/blob/2a1408b8a73504f348d1126783a975d8d59abf6a/src/inplace_restore.go#L161-L176)
4. **同名目标覆盖：**测试目录已存在去后缀目标时，`os.Rename` 替换了原有文件；该观察基于本次 Linux 测试环境。[重命名逻辑](https://github.com/penv13/c3rb3r-inplace-rescue/blob/2a1408b8a73504f348d1126783a975d8d59abf6a/src/inplace_restore.go#L234-L239)
5. **失败后仍清理勒索信：**使用错误材料处理测试目录时，密文样本保持原样，但默认开启的清理行为仍删除了合成勒索信。[默认参数及目录遍历](https://github.com/penv13/c3rb3r-inplace-rescue/blob/2a1408b8a73504f348d1126783a975d8d59abf6a/src/inplace_restore.go#L245-L252)

另有文字与实现的区别：部分说明把目标称作文件尾“最后 48 字节”，本次对应样本的 AES 封装记录位于 **588 字节 Footer 的前 48 字节**。使用前应核对具体样本布局。

## 本案证据试跑与适用范围

另使用本机有效 Footer 记录，对三个已保存内存或派生材料中的限定副本试跑扫描器，合计 **23,203,840 字节，候选命中 0**。这不是使用该工具对全部 RAM 和交换区重新扫描的结果，也不能证明其他未覆盖材料不存在密钥。原始证据没有被待测程序修改。

该工具作者报告的成功案例使用了加密进程存活时保存的独立进程内存；案例规模是作者自述，本页没有独立重验。对本案而言，工具可在将来取得并验证匹配材料后作为实现参考，目前不能弥补缺失的会话材料。原位覆写与截断会改变输入文件；Btrfs 的实际额外空间开销也受 CoW、快照和元数据影响。

测试使用的合成数据、运行回执及本机取证材料保持私有，摘要和核对范围见[脱敏证据索引 E43](../evidence/evidence-index.json)。没有以这些测试结果宣称第三方实际案例或本机数据已完成恢复。
