GRUB 的安装补丁字段解释参照 [GRUB 维护源码中的 BIOS boot header 定义](https://github.com/rhboot/grub2/blob/master/include/grub/i386/pc/boot.h)。磁盘内 core 与模板存在三个字节位置的差异，已保留原始定位，没有把整个 core 宣称为与模板逐字节相同。这里的模板也来自同一台受影响机器，不能代替事件前可信基线。

一个容易误判的细节是 `/zImage` 外层头部保留 `4.4.180`，但其实际 ELF 内核载荷的 banner 是 **4.4.302+、#69057**；initramfs 内 **184 个模块**的 vermagic 也为 `4.4.302+`，与当前采集的内核版本吻合。不能仅凭外层旧字符串判断内核被替换。

当前 `rc.subr` 与本机 `etc.defaults` 副本相同；这是先前清理已确认持久化后的状态，历史恶意追加证据仍然保留。当前 boot ID 与首次驻留排查保存值一致，未发生本轮取证期间的 NAS 重启。

**这些结果支持“目前检查到的启动结构仍连贯”，不能保证下一次重启正常，也没有完成 BIOS/固件或自定义引导器的外部可信认证。** 本轮没有为验证而重启机器。
