## 实际操作顺序

1. 读取可用空间、RAM 地址范围、kcore ELF program headers、交换设备表和原服务状态。选用有约 3 TB 空间的另一数据卷，创建独立目录，限制为设备所有者访问；没有覆盖旧证据。
2. 保存 kcore ELF 头与 notes、内核基础信息及第一份进程快照。
3. 读取九个有实际物理地址的 kcore `PT_LOAD` 区域，按区域分别保存。优先采集高地址大区间，各文件保留自身起止时间和流式 SHA-256。
4. 与 `/proc/iomem` 的 `System RAM` 地址范围逐段比较，发现 kcore 未覆盖一段 2,048 字节的非整页尾部。以只读方式从 `/dev/mem` 补存并独立回读匹配，使本轮声明的 System RAM 范围没有剩余缺口。
5. 读取四个 zram 的完整逻辑设备以及 `/dev/md1`。没有执行 swapoff、清空或重建交换空间。
6. 保存 kpageflags、kpagecount、kpagecgroup、第二份进程及线程快照和有界 pagemap 元数据。进程资料打包为归档，成员摘要保存在每个归档内的 `MEMBER_MANIFEST.json`。
7. 对 NAS 上保存的全部主数据重新读取并与采集摘要比较；另核验补充的 2 KB 数据。随后生成主清单、摘要列表、补充覆盖说明、中文说明和封存回执。
8. 文件设为 `0400`，目录设为 `0500`；同步本轮目录元数据。再次核对封存回执摘要、权限、剩余临时文件和原恢复服务状态。

RAM 与交换输出均实际使用直接 I/O。全零块保存为稀疏区间，回读时仍按完整逻辑字节参与 SHA-256；逻辑内容没有因稀疏存储改变。采集没有停止已有进程、冻结系统、重启 NAS 或更改原服务。登录、程序运行和备份写入会改变在线现场，因此这不是原子快照。
